# 跨会话引用默认带入所在问答轮次

版本 0.3.12-rc2.5，配合 Maintenance Engine 0.1.33-rc2.7 / 插件 0.2.26-rc2.6。

发送跨会话引用时，Host 在验证固定来源后读取所选回复所在轮次，把有界的 `initialContext` 与重点选文一起送入已有提交事务。模型首次即能看到来源问题和完整回复，超长时明确标记 `turnComplete: false` 及继续游标。完整首轮的游标通向更早历史；不会自动读取所有上游或引入所选回复之后的内容。

`initialContext` 是会话引用材料，与 Obsidian 的 `dsh-reference-documents` 分开表达。系统说明要求模型按需自行调用已经授权的上游只读工具，不能因为文档列表为空就宣称只收到选文，也不应再次向用户索要读取许可。

所有引用共同分配准备额度，已有笔记和引用描述也计入；后续工具预算扣除本轮已带入材料。模型未知用量、超额返回、来源变化或不可读取仍按现有规则保守处理。草稿不保存首轮副本；提交采用原有日志和请求消息保证重放一致，没有新增全量来源备份。旧提交不含该可选字段，序列化摘要与读取兼容性保持不变。

验证覆盖：实际提交预览和原生消息包含完整问答；成功重试不重复读取或发送；日志序列化/反序列化摘要一致；跨目标与来源版本校验；多引用额度分配；后续工具扣除初始用量；下一轮额度不重复扣除历史输入。配套部署与验证记录见本次 artifacts 目录。

实际引用验证补充：来源轮次中的大工具输出曾占满初始额度。默认材料现在只优先提供本轮问题和选中的已完成回答，中间 assistant 步骤及工具输出不预载；`omittedIntermediateItems` 说明省略数量，`detailsCursor` 提供按需读取入口。`turnComplete` 表示这些问题/回答正文完整，不代表读过省略的工具过程；完整后的 `nextCursor` 仍指向更早轮次。工具很多的来源也必须能先看到原问题和所选回答。
