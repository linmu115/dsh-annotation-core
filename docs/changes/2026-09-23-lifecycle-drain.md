# Core 生命周期收尾（2026-09-23）

运行基线：DSH **0.1.5-rc.2** / web profile。源码以 0.3.12-rc2.28 为基础，本次记录不代表已发布或安装。

用户要求保持 Core、Bridge 独立，并补充符合 DSH 生命周期约定的卸载/重载边界。Core 仍不导入或硬依赖 Bridge、Maintenance：来源能力通过 Core 的公开 adapter 合同注册。

## 行为

- 回链、待提交撤销、已提交解除引用队列，在卸载时停止接收新工作、清除重试定时器，并等待已接收的来源调用和持久化回执完成。
- 多条并行作业即使其中一条失败，也先等待其余作业完成；调用方仍收到失败，不因第一个拒绝提前关闭存储。
- 启动恢复任务和定期上游恢复任务由生命周期跟踪；停止后不再开始下一项恢复。
- 提交协调器通过生命周期 AbortSignal 取消可取消的准备/等待步骤，并等待已开始的事务记录收尾。已经入队但尚未确认的提交保留为 unresolved，以便下次恢复，不伪造成功回执。
- 异步打开存储期间卸载时，Cordis 会先使 fiber 失效再等待 apply 完成；提前注册关闭所有者并核验 fiber 身份，晚到存储域直接关闭，不继续挂载服务。
- Cordis 会并发运行清理回调，因此 annotation domain 和 Core 自己创建的 session-extension domain 共用停止屏障；先等待上述工作，再排空存储写入并关闭域。

来源 adapter 公共接口没有新增强制参数、取消要求或其他插件依赖。旧调用方仍可调用 dispose；宿主生命周期现在会等待它返回的 Promise。已经发出的来源写入若不支持取消，将等它结束；不使用假超时关闭正在使用的存储。

## 本次验证

Node 24.7.0 / pnpm 11.19.0；类型检查、完整构建通过；51 个文件、308 项默认测试通过（原 300 项 + 新增 8 项）。新增覆盖：回链执行中停止、撤销失败后停止重试、删除回执 drain、提交 settlement 取消且记录保留、启动恢复 flush 中停止、真实 Cordis fiber 卸载后重开 JSON 域读取回执，以及两个存储域异步打开中卸载。

未进行运行实例安装/热重载、全部消费者动态替换或界面验收。未重跑可选的宿主源码集成测试。Adapter 若永不完成会阻塞正常卸载；公共 adapter 协议不提供强制取消，因此本轮没有将它标为已解决。
