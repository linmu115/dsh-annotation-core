# 草稿引用移除同步

输入框气泡及引用对话框使用 `removeReference` 移除待发送引用；失败认领的回滚使用 `discardPendingOperation`。此前这两条路径只删除 pending 条目，未保存明确删除标记。Maintenance 镜像按设计不从缺席推导删除，因而已经同步的 pending 条目会残留。

两条实际移除路径现在把轻量 `deletedReferences` 标记与原 pending 修改一起持久提交。只有确实移除了目标条目才写标记；被其他已提交操作持有的同一条目、其他 pending 条目和已发送引用保留。目录按既有协议导出 `state: deleted`、空摘录、空评论、空来源，重启与分页重放仍可收到正向删除。

普通草稿移除的标记增加可选内部字段 `disposition: discard`。`PendingDiscardOutbox` 据此保留原来的取消捕获流程；明确解除关系以及没有该字段的旧删除记录继续走精确的关系删除回执流程。`notifySource: false` 的认领回滚只写本地删除标记，不创建全局来源清理任务。删除标记只包含 ID、类型、时间和处理方式，不包含正文或快照；原有待确认来源清理任务的生命周期保持不变。

核查其余原生移除路径：`deleteReferenceLink` 和图授权撤销本来已有明确删除标记；完成提交只是把 pending 移入 sent 集合，不是删除。此次无需为它们推导额外删除。

合成验证：目录测试新增 5 项，涵盖 DSH 与 Obsidian 草稿的真实 Remote 移除入口、订阅通知、未删除条目保留、清理作业结束后仍可重放删除、operation 回滚重试与重启、其他操作仍持有条目时不误删。目录、存储、草稿清理、关系删除回执和固定上游 5 个测试文件共 62 项通过，类型检查、`npm run build` 与 `git diff --check` 通过。未操作真实实例或真源数据，版本保持 `0.3.12-rc2.10`。
