# 引用发送版本冲突修复

## 问题与行为

Obsidian 引用之后再加入跨会话引用时，后端引用集已经到版本 2，旧输入框状态仍可能按版本 1 发送。原生命令入口可能比创建它的 React 输入框组件存活更久；单次刷新请求还可能比后续流式更新更晚返回，造成状态回退。

发送前重新读取后端引用集。原生发送入口按输入框及会话身份查找当前绑定，旧绑定卸载不会移除替代它的新绑定；已销毁绑定及跨会话调用会被阻止。刷新结果不能覆盖更新的引用版本。

若准备期间引用再次改变，保留乐观版本校验，刷新气泡并显示中文重试提示，保留正文及附件，不自动再次发送。发送进入异步核对之前就锁住重复提交；响应丢失后先核对原提交回执，已成功的相同消息直接确认成功，避免重复模型调用。

## 验证

类型检查与构建通过。全部 33 个测试文件、182 项测试通过，其中输入框相关 17 项测试覆盖旧缓存、准备期间变化、乱序刷新、组件重建、已销毁入口、不同会话隔离、丢失响应及重复点击。

作为 0.3.12-rc2.7 的独立本地修复构建安装到 0.1.5-rc.2 副本。保持现有版本兼容组合，通过单独的包路径和哈希区分新产物。仅更新 Annotation Core，并核对 suite 嵌套关系和 Maintenance 启动绑定。验收不发起真实模型回答，不清理用户引用。
